# ТЗ: лендинг Party Time — для вёрстки в Claude Code

## 0. Коротко

Делаем новый главный лендинг сети караоке-лофтов **Party Time** (Санкт-Петербург) вместо перегруженного сайта на Tilda (partytimespb.ru). Одна страница. На ней показаны **2 активные локации: Думская и Маяковская (36 залов)**. Ленинский и Комендантский — неактивные кнопки «Скоро на сайте». Пункты меню «Кухня & Бар», «Услуги», «Акции» есть в шапке, но их страницы **не верстаем**: ссылки ведут на заглушку «Скоро» (`/soon`).

Цели:
- **Вау-эффект с первого экрана.** Ультрасовременный, модный сайт, много анимации.
- **Удобство.** Зал выбирается и бронируется за 3 клика.
- **Время на сайте больше 3 минут.** Это обеспечивают каталог залов с галереями, интерактив и пошаговая форма.
- Сайт сразу готов к **будущему SEO**: семантика и разметка закладываются сейчас, ключевые слова добавим позже.

Сайт презентуют руководству, поэтому качество визуала важнее всего.

## 2. Стек

- **Astro 5** (статическая сборка, хорошо для будущего SEO) + TypeScript.
- Стили: чистый CSS с переменными из `brand/tokens.css`, CSS-модули или scoped-стили Astro. Без Tailwind, чтобы дизайн-система оставалась в одном месте.
- Анимации: **GSAP 3 + ScrollTrigger**, **Lenis** (плавный скролл), **SplitType**.
- 3D: **Three.js** только для варианта B (диско-шар в hero), загружается лениво.
- Шрифты: `@fontsource-variable/unbounded`, `@fontsource-variable/onest`, рукописный `@fontsource/caveat` (кириллица).
- Картинки: `astro:assets` (AVIF/WebP, srcset).
- Деплой: **GitHub Pages** через GitHub Actions из ветки `main`. Репозиторий: `https://github.com/stasjuicytrax-arch/Partytime.git`. Если базовый путь Pages `/Partytime/`, настроить `base` в Astro.

### Шаг 0. Подготовка
1. Открыть терминал в `C:\Users\G13\Desktop\CLAUDE\Party Time web`.
2. `git init` → `git remote add origin https://github.com/stasjuicytrax-arch/Partytime.git` → `.gitignore`: `node_modules`, `dist`, `Logo/`, `PT Брендбук.pdf`, `*.ai`. Брендбук весит 23 МБ, в репозиторий его не кладём.

7. Коммит и пуш: `chore: project setup`.

### Шаг 1. Два варианта дизайна (hero и каталог залов)
Заказчик хочет **выбрать направление**. Предварительно ему ближе **вариант A** — его прорабатываем глубже и первым, B делаем на том же уровне качества, но A — приоритет. Верстаем **hero и второй блок «Залы»** в двух вариантах на общих токенах. Каждый вариант на отдельном маршруте:
- `/` — простая страница выбора: две большие карточки-превью «Вариант A» и «Вариант B».
- `/a` — вариант A, `/b` — вариант B.

**Вариант A — «Поп-коллаж» (днём на афише).**
Референсы: golf le FLEUR, Best Prom Night, «Академия бровиста».
- Фон: «бумага» `--pt-paper` и розовый `--pt-pink`, контрастные цветные блоки встык, зерно.
- Hero: гигантское «ВМЕСТЕ И ГРОМЧЕ» (Unbounded 900, ~11vw) в 2–3 строки. Сквозь буквы и поверх них идут вырезанные фото гостей с микрофонами на цветных плашках под наклоном. Вокруг рукописные дудлы-стрелки с подписью «тут поют до 6 утра →», стикеры-звёзды цвета лайм, вращающаяся печать «ПОЁМ • ТАНЦУЕМ • ОТМЕЧАЕМ». Логотип в шапке на белой плашке.
- Анимация: коллаж «собирается» при загрузке (фото и стикеры прилетают и шлёпаются с overshoot), при движении мыши слои смещаются с разной глубиной, дудлы прорисовываются линией.
- Под hero идёт двойная бегущая строка на чёрном под наклоном −2°.
- Каталог залов: светлая секция. Карточки-«полароиды» с обводкой 2px и жёсткой цветной тенью по группе вместимости, наклон ±1°. Цены на таблетках-стикерах.

**Вариант B — «Ночной лофт» (ночью в клубе).**
Референсы: Futura, Base Club, Pinterest glass.
- Фон: `--pt-deep` с мягкими цветными «прожекторами»: размытые радиальные пятна violet, pink и sky медленно плавают.
- Hero: в центре **3D диско-шар** (Three.js: зеркальные грани, отражения в цветах палитры, медленное вращение, реакция на курсор, блики-«зайчики» бегают по фону). Огромная надпись «ВМЕСТЕ И ГРОМЧЕ» проходит за шаром и перед ним (слои). Glass-карточки с фактами («36 залов», «до 06:00») парят по краям. Фото гостей в дуотоне по краям.
- Анимация: при загрузке вспыхивает свет и шар «включается», заголовок разлетается по буквам (SplitType). На скролле шар уезжает вверх и уменьшается, становясь иконкой в шапке.
- Каталог залов: тёмная секция, карточки с неоновым контуром цвета группы при hover, стеклянная плашка с названием внизу, листание фото курсором.

**В обоих вариантах** каталог залов полностью рабочий: переключатель локаций (2 активные + 2 неактивные), фильтр по гостям, карточки из `rooms.json`, модалка зала с галереей и кнопкой «Забронировать этот зал» (пока ведёт на якорь `#booking` с параметрами). Мобильная версия обязательна для обоих вариантов.

После шага: `/impeccable critique` по каждому варианту → исправить → `/impeccable polish` → пуш → деплой на Pages → **прислать заказчику ссылки на /a и /b и остановиться до его выбора.**

### Шаг 3. Финал
- `/impeccable audit` + `/impeccable polish`, проверка на AI-шаблонность («slop»): нет одинаковых карточек-иконок в сетке, нет стоковых градиентов, у каждого блока свой композиционный ход.
- Lighthouse (mobile): Performance ≥ 85, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 95.
- Проверка на 375 / 768 / 1280 / 1920 px, в Safari iOS и Chrome Android.
- `prefers-reduced-motion`: все тяжёлые анимации отключаются.
- Пуш и деплой. Прислать ссылку.

## 4. Функциональные требования

- **Каталог залов** строится только из `content/rooms.json`, без хардкода. Сортировка по умолчанию: по вместимости, от больших залов к меньшим. При смене локации карточки анимированно перестраиваются (GSAP Flip). У залов Маяковской пока по одному фото: слайдер скрывается, вместо него лёгкий zoom фото при hover. Площади и точной вместимости у этих залов нет, показываем только группу «6–8 гостей».
- **Неактивные локации** выглядят как кнопки: серые, с бейджем «скоро», не кликаются, при hover показывают tooltip «Скоро на сайте». Нужен `aria-disabled`.
- **Модалка зала**: открывается по клику, URL меняется на `#room-<slug>` (ссылкой можно поделиться). Внутри галерея со свайпом и стрелками, название, tagline, описание, бейджи, цена «от N ₽/час», блок «Входит в аренду», CTA. Закрытие по Esc, крестику и клику по фону.
- **Форма бронирования**: шаги и поля из `content.md` §9. Данные сохраняются в `localStorage` между шагами. Есть валидация телефона (маска +7). Отправка пока в заглушку (`console` + экран успеха). Цель интеграции — **RestoPlace** (туда сейчас падают брони со старого сайта); способ подключения уточняется, поэтому вся отправка изолирована в `src/lib/lead.ts`. Кнопка «Забронировать этот зал» из модалки предзаполняет шаги «Где» и «Зал».
- **Мессенджеры**: плавающая кнопка «Написать нам» в правом нижнем углу (Telegram, VK, MAX). Появляется после первого экрана.
- **Телефоны** — ссылки `tel:`, адреса — ссылки на Яндекс Карты.
- **Удержание внимания (больше 3 минут)**: галереи залов, горизонтальная лента форматов, интерактивные стикеры (их можно перетаскивать мышью в hero варианта A), пасхалка — клик по диско-шару или логотипу включает «режим вечеринки»: фон мигает в палитре под бит, 3 секунды, с учётом reduced-motion.

## 5. SEO-заготовка (без наполнения семантикой)

- Один `<h1>` (в hero), логичные h2/h3. Секции — это `<section>` с `aria-labelledby`.
- `<title>` и `meta description`: черновые, вынести в `src/config/seo.ts`.
- Open Graph и Twitter-карточки (картинка 1200×630, сгенерировать из hero).
- JSON-LD: `Organization` + 2 × `EntertainmentBusiness`/`LocalBusiness` (адрес, телефон, часы, geo), `FAQPage` из FAQ.
- `sitemap.xml` (`@astrojs/sitemap`), `robots.txt`, канонические URL, `lang="ru"`.
- Счётчики (Метрика, Top.Mail.Ru, GTM): заготовка в `src/config/analytics.ts`, ID пустые.

## 6. Ограничения

- **Никаких контурных человечков-маскотов** из брендбука.
- Логотип **не перекрашивать** и не искажать (брендбук, стр. 20).
- Названия залов, отсылающие к франшизам («Звезда смерти», «Хогвартс», «Микки и Мини» и др.), оставляем как есть: это названия залов заказчика. Чужие логотипы и персонажей в графике сайта **не рисуем**.
- Шрифты только Unbounded, Onest и рукописный акцент. Шрифты брендбука (TT Bluescreens, PF Regal) не используем.
- Страницы Кухня, Бар, Услуги, Акции не верстаем, делаем одну страницу-заглушку `/soon`.
